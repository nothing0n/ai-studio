# AI Bot

一个可以部署在 GitHub Pages 的个人 AI 聊天工作台：默认只有个人管家，其他 Bot 由你手动创建；管家可以将问题分配给你配置的团队成员。电脑和手机共用一个网页，聊天通过 GitHub API 同步到你自己的私有仓库。

- 网页：[nothing0n.github.io/ai-studio](https://nothing0n.github.io/ai-studio/)
- 网页源码：[nothing0n/ai-studio](https://github.com/nothing0n/ai-studio)
- 私有数据：[nothing0n/ai-studio-data](https://github.com/nothing0n/ai-studio-data)

## 开始使用

1. 打开网页，进入「设置与连接 → 模型连接」。从下拉框选择平台、地域和模型，填写自己的 API Key 即可；首次已选中 OpenAI 与 `gpt-5.4`。点击「读取可用模型」可以查询账号模型列表；「测试连通性」使用当前表单发送一条简短消息，计入本网页用量，不保存配置或创建会话；在「生成参数与连接名称」中选择思考程度、随机性、生成 Token 上限和回复显示方式。ChatGPT 登录不会提供 API Key。自定义接口仍支持手填地址与模型。页面保留各平台官方密钥及文档入口。
2. 点击成员打开其会话，成员名称旁的加号新建会话。每段会话独立保存启动时的人设和经验总结，之后修改成员资料仅影响新会话。默认只有管家，其他 Bot 自行添加；管家根据你的指令、关键词或模型判断，在目标成员下新建会话并交接上下文。
3. 「GitHub 同步」已预选 `nothing0n/ai-studio-data`。填写访问令牌后，可点击「读取仓库」「读取分支」，从下拉框选择已授权的私有仓库和分支，也可手动填写。通常保持「默认分支（自动）」。点击「测试连通性」只检查访问，不保存凭据或写入仓库；「连接并同步」才保存配置并同步，首次同步会验证写入权限并初始化数据目录。
4. 在另一台设备打开相同网页，配置同一个数据仓库和访问令牌即可同步历史。模型密钥也需要在每台设备分别填写。

GitHub 访问令牌在 [GitHub 官方设置](https://github.com/settings/personal-access-tokens/new) 创建。选择 **Only select repositories → ai-studio-data**，仓库权限只需 **Contents: Read and write**，并设置有效期。不要在源码、聊天或 issue 中填写真实令牌。

## 已包含的功能

- 按成员分组、组内按会话排列，切换成员会打开其最近使用的会话。
- 可编辑成员名称、职责、人设、经验、关键词、颜色和模型连接；支持上传头像。
- 经验手动维护，也可从当前会话生成可编辑草稿，检查后点击「保存角色」才生效。关闭资料不会保存草稿，旧会话继续使用原来的经验。
- 多个模型连接；角色可以使用指定连接，或跟随管家的默认连接。
- 输入框右下角直接选择当前厂商的模型，保留会话和草稿；切换会修改该连接的默认模型，应用于使用此连接的成员之后的请求。下拉优先读取账号模型列表，读取失败时保留常用模型；生成中不可切换。
- 平台、接口地域、常用模型和生成参数使用下拉框；不支持的参数自动禁用，读取模型列表不会产生聊天调用。
- 会话右上角以简约单行常显账户余额入口和本浏览器用量，支持今日、本月、累计筛选。手机上显示在聊天顶部，滚动消息时保持可见。
- 管家转接时在目标成员下创建独立会话，带入此前上下文；原会话保留在管家下面。
- 流式文本、停止生成、失败提示、重试最近的问题、Markdown 与代码块。
- 本机保存、重命名/删除会话、导入/导出不含凭据的 JSON 备份。
- 每轮完成后同步、页面重新获得焦点时同步、手动同步。
- 以消息 ID 合并电脑/手机的新增消息；冲突时重新读取 GitHub 文件版本并重试。
- 删除标记避免旧设备复活已删除会话；并发删除与新增产生恢复副本。
- 并发修改成员配置时保留冲突副本；同一会话在人设不一致时保留独立副本。
- 手机抽屉导航、键盘操作、中文输入法兼容。

## 数据和密钥

GitHub Pages 只提供网页。所有应用逻辑运行在浏览器里，没有额外的应用服务器。

私有仓库的数据结构：

```text
studio-data/
  settings.json               # 成员、人设、经验、压缩头像、模型配置；不含密钥
  conversations/<uuid>.json    # 会话归属、启动时的人设与经验、消息、转接上下文
```

GitHub PAT 和模型 API Key 保存在当前标签页的 `sessionStorage`，不写入持久聊天数据、仓库或导出备份。刷新页面可以继续使用；新的浏览器会话需要重新填写，浏览器的会话恢复行为可能有所不同。可以在「数据与备份」主动清除密钥。网页脚本可以读取会话密钥，因此只使用你信任的源码和部署。

头像会在浏览器裁剪、压缩为 128 × 128 图片，只保存压缩后的图片，不上传原文件。成员资料和头像随私有仓库同步。当前数据格式为 v3，兼容导入 v1、v2；旧会话首次继续聊天时按当时的成员资料初始化。升级后请刷新其他设备的旧页面再同步。

模型请求只发往你配置的地址，GitHub 请求只发往 `api.github.com`。当已保存密钥对应的模型地址改变时，需要重新填写密钥。模型回复经过 HTML 清理，不加载回复里的图片或执行脚本。

## 余额与用量的口径

- **账户余额**：DeepSeek、Kimi 的官方接口会直接返回余额，保留币种与查询时间。首次连接、模型请求结束以及回到页面时按需刷新，也可手动刷新。自定义中转地址不会被当作官方接口查询。
- **OpenAI 余额**：普通项目密钥没有受支持的预付余额查询接口，页面显示「余额 ↗」并链接到账单页面，悬停可查看查询限制说明。组织 Usage / Costs 接口需要更高权限，且已产生费用并不等于剩余余额；本网页不要求管理员密钥。其他未接入余额的平台提供官方控制台链接。
- **本网页用量**：按当前模型连接及接口地址统计，从此版本启用后记录在本浏览器。包括聊天、管家分配、经验总结、连接测试以及重试；模型列表与余额查询不计入。切换模型仍在同一连接累计，换密钥不清零。
- 只累计 API 返回的真实 Token 数。缓存 Token 已包含在输入中，思考 Token 已包含在输出中，不重复相加。停止、断流或接口未返回 usage 时显示「用量未返回」，数字仅为已报告部分，不代表免费或零消耗。
- 用量账本按独立请求保存在 `localStorage`，不含凭据或消息正文，不上传 GitHub，也不包含在聊天备份中。其他设备和网站之外的调用不在统计内，历史聊天无法追溯补算。清除网站数据会删除本浏览器统计。
- Kimi 当前预设使用 `kimi-k2.6` 非思考模式；需要回传思考内容的 K3 暂不放入自动模型列表。其他平台的兼容层仍以其官方支持及账号权限为准。

接口依据：[OpenAI 流式用量](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)、[OpenAI 组织用量](https://developers.openai.com/api/reference/resources/admin/subresources/organization/subresources/usage/methods/completions)、[DeepSeek 余额](https://api-docs.deepseek.com/api/get-user-balance/)、[Kimi 余额](https://platform.kimi.com/docs/api/balance)。

## 当前边界

- 模型服务必须支持浏览器跨域调用（CORS）。如果服务禁止浏览器直接访问，需要另行部署受保护的转发服务；GitHub Pages 本身不能提供该功能。
- 托管及仓库同步可以使用免费额度，模型调用按供应商规则计费。首次管家智能分配可能多调用一次模型。
- 每次模型请求携带最近 40 条有效消息，以及本次会话启动时的人设和经验。经验总结最多 20,000 字符，从会话生成时使用最近 40 条有效消息；没有自动写入长期记忆或文件知识库。
- 聊天在浏览器中即时保存，在一轮回答完成后上传，不逐字产生 Git 提交。单个远端会话文件限制为 950 KB，超限时保留本机数据并提示导出、开启新会话。
- GitHub 有请求频率限制；失败时保留本机数据，修复连接或额度后重试。
- 删除会话不等于清除仓库 Git 历史。请勿将 API 密钥混入聊天正文。
- 本机聊天使用浏览器存储，有空间上限。清理网站数据前先同步或导出。多人协作、高频数据写入不属于这个版本的目标。
- 主动停止后保留已收到的内容，重试不会自动发起，也不会重复插入用户问题。

## 本地开发

需要 Node.js 24 和 npm：

```sh
npm ci
npm run dev
```

```sh
npm test          # 模拟流式协议、同步冲突、数据校验；不调用真实模型
npm run build    # 输出 dist/
npm run test:ui  # 桌面和手机浏览器测试；默认使用本机 Microsoft Edge
```

浏览器测试使用模拟模型和模拟 GitHub，不需要真实密钥。其他环境可在 `playwright.config.js` 调整浏览器 channel。

## 发布

仓库的 Pages 构建方式设为 **GitHub Actions**。推送到 `main` 后，`.github/workflows/deploy.yml` 自动安装依赖、运行逻辑测试、构建并发布 `dist`。

所有资源使用相对路径，因此支持 `https://用户名.github.io/仓库名/`。无需将任何 GitHub PAT 或模型密钥配置到 Actions Secrets；网页运行时由本人填写。
